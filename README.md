# Work Life Balance

Локальный трекер работы, отдыха и AFK для Windows. Версия 0.4: учёт приложений и вкладок Firefox, AFK, трей, рабочие правила, редактирование истории, графики, календарь, экспорт, копии и восстановление. Данные не отправляются во внешние сервисы.

## Запуск готовой сборки

После сборки запустить `.artifacts/release/WorkLifeBalance.Host.exe` или `scripts/start.ps1`. Значок приложения появится в трее. Интерфейс: <http://127.0.0.1:47831>. Установка/обновление: `.artifacts/release/install.ps1` из обычной PowerShell; [руководство](docs/user-guide.md).

- `Win + Shift + N` переключает AFK, даже когда активна другая программа. Ручной AFK выключается тем же сочетанием или кнопкой, а не движением мыши.
- Автоматический AFK включается через 30 минут без ввода и переносит в AFK весь период с последнего действия. Порог можно увеличить или отключить автоматический режим.
- Изменения рабочего списка приложений применяются к будущему времени или также к истории, по выбору. Ручные правки сохраняются. Firefox по умолчанию считается отдыхом; список «Рабочие сайты» автоматически относит новые посещения указанных доменов и поддоменов к работе.
- В истории можно изменить категорию всей записи, части интервала или выделенной группы и отменить правку. Исходные наблюдения сохраняются отдельно.
- Для вкладок Firefox зарегистрировать локальный помощник и установить расширение: [инструкция](docs/firefox.md). В обычный профиль расширение автоматически не устанавливается.
- При смене порта требуется перезапуск. Если порт занят, его можно изменить через меню трея без работающего веб-интерфейса.
- Полный выход: меню трея → «Выход» или `scripts/stop.ps1`. Закрытие вкладки не останавливает учёт.

Обычный запуск хранит SQLite-базу и локальный журнал в `%LOCALAPPDATA%\WorkLifeBalance`. Тестовые данные в `.local` не используются обычным запуском. История содержит executable, интервалы и, при подключённом расширении, очищенные адреса и заголовки активных вкладок. Содержимое страниц и ввод пользователя не собираются.

## Разработка

Для разработки требуются Windows x64, .NET SDK 10.0.401 (либо более новый патч этой feature band), Node.js 22.18+ и npm. Скрипты также распознают локальный SDK в `.artifacts/dotnet10`. Поставка self-contained win-x64, с .NET 10.0.12: пользователю не нужны .NET, Node.js и Vite. Разработческие скрипты отключают телеметрию CLI; runtime приложения не вызывает CLI.

```powershell
./scripts/build.ps1
./scripts/start.ps1
```

Сборка скачивает зависимости разработки; установленное приложение работает локально и не требует Node.js или Vite. Все версии зафиксированы в проектах и lock-файлах. Перед пересборкой остановить приложение, иначе Windows удерживает загруженные DLL.

Для редактирования frontend запустить backend, затем:

```powershell
cd src/web
npm run dev
```

Vite доступен только на `127.0.0.1:47832`, проксирует API на `47831`. Производственный интерфейс отдаёт сам .NET-host, отдельный dev-сервер не нужен.

## Проверки

```powershell
./scripts/test.ps1
```

Backend/native-тесты проверяют AFK, SQLite, восстановление, DST, Windows, браузерный протокол, миграцию, правки, dashboard и управление данными. Дополнительно выполняются 6 тестов сборщика вкладок. Native-тесты требуют интерактивной Windows-сессии. Результаты текущего прогона: [итерация 4](docs/iteration-4.md).

Браузерные тесты работают с реальным backend и временно меняют настройки. Запускать их только с отдельной тестовой базой, а не с личной историей:

```powershell
# Подготовить НОВУЮ тестовую базу на отдельном порту:
dotnet run --project tools/WorkLifeBalance.Smoke -- --seed "C:\temp\wlb-browser-test" 47833
Start-Process -FilePath '.artifacts/release/WorkLifeBalance.Host.exe' -ArgumentList '--data-dir', '"C:\temp\wlb-browser-test"' -WindowStyle Hidden
cd src/web
$env:WLB_TEST_URL = 'http://127.0.0.1:47833'
npm run test:e2e
```

Тесты используют установленный Microsoft Edge в headless-режиме и сохраняют desktop/mobile снимки в `src/web/test-results`. Они проверяют реальные настройки, правила, AFK/паузу, отсутствие внешних запросов страницы, CSRF и Origin/Host-проверки. Для остановки тестового экземпляра передать тот же `--data-dir` и `--shutdown`.

Расширенная сквозная проверка Windows:

```powershell
dotnet run --project tools/WorkLifeBalance.Smoke -- ".artifacts/release/WorkLifeBalance.Host.exe" ".local/native-check"
```

Порт `47831` должен быть свободен. Проверка запускает собственные скрытые экземпляры, генерирует только согласованное сочетание `Win + Shift + N`, проверяет занятый порт и аварийно останавливает только свой процесс для теста восстановления. На этапе AFK требуется несколько секунд без ввода; при непрерывном вводе этот подпункт честно помечается `SKIP`. Повторные проверки лучше запускать с новым тестовым каталогом.

## Границы текущей версии

- Подписанный Firefox 0.2.0 установлен и подключён в обычном профиле: [результат](docs/firefox-signing.md). ZIP сборки остаётся неподписанным, используйте полученный XPI.
- Часовой пояс отчётов системный. Старые пробелы до SQLite v3 невозможно достоверно разделить на паузы и остановки трекера.
- Автозапуск включается явно в настройках. Срок хранения используется для подтверждаемой очистки, без фонового удаления. Восстановление заменяет историю, но сохраняет текущие настройки. Копии автоматически не удаляются.
- Поставка подписанного Firefox XPI готова; EXE и PowerShell-установщик не имеют Authenticode-подписи. Перезагрузка Windows, видимость уведомлений и обычная пользовательская установка требуют ручной приёмки.
- Уведомления сейчас используют нативный `NotifyIcon.ShowBalloonTip`. Windows определяет внешний вид и может скрывать их настройками уведомлений/«Не беспокоить». Переходы состояния не зависят от отображения уведомления.
