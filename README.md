# Work Life Balance

Локальный трекер рабочего времени и личных дел для **Windows x64**. Работает в фоне, определяет активное приложение и вкладку Firefox, разделяет время на работу, отдых и AFK. Статистика, календарь и задачи доступны в браузере: **http://127.0.0.1:47831**.

Это личный инструмент, а не сервис контроля сотрудников. Он измеряет активность приложений, а не реальную продуктивность. Аккаунт для работы не нужен; история не отправляется на серверы.

## Возможности

| Раздел | Что умеет |
| --- | --- |
| Учёт | Время приложения на переднем плане, объединение наблюдений в интервалы |
| Рабочие правила | Редактируемые списки программ и сайтов, добавление из запущенных процессов |
| AFK | Автоматический режим с настраиваемым порогом и ручной режим по глобальному хоткею |
| Windows | Трей, уведомления о переходах AFK, пауза, учёт сна и блокировки, необязательный автозапуск |
| Firefox | Активные вкладки: очищенный адрес, домен, заголовок и интервалы посещения |
| История | Изменение категории записи, части интервала или группы; отмена исправлений |
| Дела | Задачи с весом 1–5, планирование, перенос незавершённого и рекап выполненного |
| Отчёты | Доля работы, почасовой график, приложения, месячные и недельные итоги |
| Календарь | Две цветовые половины дня: часы работы и вес выполненных задач |
| Данные | CSV/JSON, локальные SQLite-копии, восстановление и подтверждаемая очистка |

## Установка

### Что находится в репозитории

В Git хранятся **исходники, тесты и документация**. Базы, локальные настройки, зависимости, собранные EXE и подписанный Firefox XPI не включены. Клонирование репозитория само по себе не устанавливает приложение.

Основной путь ниже: собрать исходники, затем установить полученную папку. Если у вас уже есть готовая сборка, переходите к шагу 3: .NET SDK и Node.js для её запуска не нужны.

### 1. Подготовьте окружение

Для сборки нужны:

- Windows x64 и PowerShell в обычной пользовательской сессии.
- Git для скачивания через `git clone`.
- .NET SDK **10.0.401** или совместимый более новый патч ветки 10.0.4xx, согласно `global.json`.
- Node.js **22.18+** и npm.
- Интернет для первоначального скачивания зависимостей.
- Firefox **142+**, если нужен учёт вкладок. Без расширения учёт программ продолжает работать.

Проверьте доступность инструментов:

```powershell
git --version
dotnet --list-sdks
node --version
npm --version
```

Права администратора для обычной установки и работы не требуются. Используйте PowerShell, открытую через меню Windows: регистрация Firefox из изолированной среды агента может оказаться невидима вашему браузеру.

### 2. Скачайте и соберите проект

```powershell
git clone https://github.com/4pOnk/Work-Life-Balance.git
cd Work-Life-Balance
./scripts/build.ps1
```

Последующие команды, если не указано иное, выполняются из корня репозитория.

Скрипт восстановит зафиксированные зависимости, соберёт интерфейс, трекер и помощник Firefox в **`.artifacts/release`**. В этой папке уже есть .NET runtime: для дальнейшей работы Node.js, Vite и отдельная установка .NET не нужны.

Скрипт использует конфигурацию `Release`: это режим компиляции, а не публикация релиза. На GitHub или в Mozilla он ничего не отправляет.

> Перед повторной сборкой закройте трекер через трей и завершите Firefox, если он использует помощник из обновляемой папки. Windows может удерживать файлы запущенного приложения.

### 3. Установите приложение

Закройте все экземпляры Work Life Balance, включая тестовые, и Firefox. Затем:

```powershell
./.artifacts/release/install.ps1 -Launch
```

Если получили готовую папку отдельно, откройте PowerShell **в этой папке** и выполните:

```powershell
./install.ps1 -Launch
```

Установщик копирует приложение в `%LOCALAPPDATA%\Programs\WorkLifeBalance`, создаёт ярлык в меню «Пуск», регистрирует помощник Firefox для текущего пользователя и сохраняет существующие данные в `%LOCALAPPDATA%\WorkLifeBalance`. Параметр `-Launch` запускает приложение и открывает статистику.

Сам по себе запуск `scripts/install.ps1` из исходников не подходит: установщику нужна собранная папка. Не переносите один EXE отдельно от остальных файлов.

### Альтернатива: запуск прямо из сборки

Можно не копировать приложение в установленный каталог:

```powershell
./scripts/register-firefox.ps1
./scripts/start.ps1
```

Регистрация нужна только для Firefox. В этом варианте программа и помощник работают из `.artifacts/release`. После перемещения репозитория повторите регистрацию.

**После обычной установки `register-firefox.ps1` не нужен:** установщик уже зарегистрировал помощник, а этот скрипт переключит Firefox на папку сборки. Выберите один основной способ запуска, чтобы не путаться между копиями.

Данные в обоих вариантах сохраняются в `%LOCALAPPDATA%\WorkLifeBalance`, не рядом с EXE.

## Подключение Firefox

Для связи нужны запущенный трекер, зарегистрированный локальный помощник и расширение. Открытая страница статистики не обязательна.

### Постоянная установка расширения

1. Установите приложение или зарегистрируйте помощник, как описано выше.
2. Получите **подписанный XPI** Work Life Balance. Версия расширения 0.2.0 подписана Mozilla; сведения о файле есть в [документации подписи](docs/firefox-signing.md). Файл не хранится в Git. Если его нет в полученной сборке, запросите его у владельца проекта.
3. Откройте в Firefox `about:addons`.
4. Нажмите шестерёнку → **«Установить дополнение из файла…»**.
5. Выберите `firefox-extension-signed.xpi` и подтвердите установку.
6. Запустите трекер, откройте обычную вкладку Firefox и проверьте подключение в панели расширения или веб-интерфейсе.

При обновлении только трекера уже установленное подписанное расширение 0.2.0 переустанавливать не нужно.

Сборка создаёт **неподписанный ZIP** `firefox-extension.zip`. Он не заменяет XPI и не подходит для постоянной установки в обычный Firefox. Если до сборки положить полученный подписанный файл в `.artifacts/work-life-balance-firefox-0.2.0-signed.xpi`, скрипт включит его в итоговую папку под именем `firefox-extension-signed.xpi`. Сам скрипт подпись не создаёт.

### Временная установка для разработки

Откройте `about:debugging#/runtime/this-firefox`, нажмите **«Загрузить временное дополнение…»** и выберите `extensions/firefox/manifest.json` из репозитория. Оно будет работать только до перезапуска Firefox. Отключать проверку подписей не требуется.

Подробности: [установка и протокол Firefox](docs/firefox.md).

## Первый запуск

1. Запустите Work Life Balance из меню «Пуск» или через `scripts/start.ps1` при работе из сборки.
2. Откройте [локальный интерфейс](http://127.0.0.1:47831), если он не открылся автоматически.
3. Проверьте статус учёта и активное приложение.
4. Настройте рабочие программы и сайты.
5. Выберите порог AFK: по умолчанию **30 минут**.
6. При необходимости включите **«Запускать при входе в Windows»** в разделе «Данные и запуск».
7. Добавьте первые задачи в раздел «Дела».

Закрытие вкладки статистики **не останавливает учёт**. Управление остаётся в трее, а хоткей работает при любом активном окне. Повторный запуск открывает интерфейс уже работающего экземпляра, а не второй сборщик для тех же данных.

## Учёт времени и AFK

### Работа и отдых

Учитывается только приложение **на переднем плане**. Открытый в фоне Blender не добавляет рабочее время, пока вы пользуетесь другой программой. Замеры выполняются примерно раз в секунду, поэтому границы переключений имеют соответствующую погрешность.

Рабочие приложения относятся к работе, остальные по умолчанию к отдыху. Для Firefox действуют отдельные правила сайтов. Отсутствующие сведения об активном окне обозначаются явно.

### Автоматический AFK

AFK означает отсутствие ввода мышью или клавиатурой. Когда простой достигает порога, **весь промежуток с последнего ввода** становится AFK, а не только время после срабатывания порога.

Например: последний ввод в 14:00, порог 30 минут. В 14:30 трекер перенесёт в AFK период начиная с 14:00. До этого статистика за него предварительная, поэтому итог работы или отдыха может уменьшиться после обнаружения простоя.

В настройках можно увеличить порог, в том числе до двух часов и больше, или отключить автоматический AFK. Ввод завершает автоматический режим. Увеличение порога само по себе не возвращает уже подтверждённый AFK в работу; ошибку можно исправить в истории.

**Видео само по себе не считается вводом.** Для длительного просмотра увеличьте порог или отключите авто-AFK. Добавление сайта в рабочие не отменяет AFK.

### Ручной AFK

Глобальный хоткей по умолчанию: **`Win + Shift + N`**.

- Первое нажатие включает ручной AFK с текущего момента, без изменения прошлого.
- Повторное нажатие возвращает к учёту активности.
- Движение мыши и ввод не выключают ручной AFK.
- Во время автоматического AFK нажатие означает явный возврат.
- При паузе учёта хоткей не возобновляет сбор.

Переключение также доступно в трее и интерфейсе. При ручном и автоматическом входе/выходе показываются уведомления Windows. Если сочетание занято или недоступно, задайте другое в настройках. После полного выхода из программы хоткей не работает.

### Пауза, сон и выход

**Пауза** прекращает сбор и отражается отдельно от AFK. Возобновить его можно в интерфейсе или трее. Блокировка и сон прекращают начисление активного времени; известное отсутствие учитывается как AFK, если сбор не был на паузе.

Для полного завершения выберите **«Выход»** в трее. При запуске из репозитория также есть `./scripts/stop.ps1`. Когда трекер не запущен, время не восстанавливается задним числом: в истории остаётся пробел. После аварии учитывается только надёжно сохранённый участок.

## Рабочие приложения и сайты

### Программы

Начальные правила: `blender.exe`, `Unity.exe`, `devenv.exe`, `Code.exe`. Любое можно удалить.

Найдите приложение в списке процессов и добавьте его в рабочие. Экземпляры сгруппированы; активное приложение выделяется. По умолчанию видны приложения с окнами, остальные процессы можно показать отдельно.

Для незапущенной программы введите **имя EXE**, например `Photoshop.exe`, без полного пути. Регистр букв не важен, PID не используется. При изменении правил выберите область применения: только будущее время или также история. Ручные исправления имеют приоритет и не перезаписываются.

### Сайты

В разделе **«Рабочие сайты»** добавьте домен или вставьте HTTP/HTTPS-ссылку. Из `https://docs.example.com/lesson?token=abc#part` сохранится только `docs.example.com`.

- Правило включает домен и его поддомены: `example.com` совпадёт с `docs.example.com`, но не с `notexample.com`.
- Добавление и удаление влияет только на **новые посещения**; прошлое исправляется вручную.
- Остальные вкладки Firefox считаются отдыхом, даже документация и обучающие видео.
- Правило процесса `firefox.exe` не заменяет правила сайтов.
- Неизвестные и приватные вкладки остаются отдыхом; AFK и ручные правки приоритетнее.

Вкладка учитывается только при активном окне Firefox. При потере соединения продолжается учёт самого Firefox без старого URL.

## Задачи и рекап

Список **«Дела»** расположен между верхней статистикой и календарём.

### Добавление и выполнение

Введите название, выберите вес **1–5** и нажмите `+`. Вес означает трудозатратность, меняет цвет строки и числового значка, но **не добавляет часы работы**. По умолчанию вес равен 1. Название ограничено 240 символами; описаний и повторяющихся задач сейчас нет.

Чекбокс отмечает задачу выполненной в текущий день. Она остаётся в том же списке зачёркнутой. Пока день не закончился, отметку можно снять: задача вернётся в открытые и исчезнет из выполненного. Карандаш открывает редактирование, корзина удаляет задачу после подтверждения.

### Планирование и перенос

Выберите будущую дату в поле «Дата задач» или календаре. Задачи на неё можно добавлять, редактировать и удалять, но нельзя отмечать выполненными заранее. Чтобы выполнить будущую задачу сегодня, сначала перенесите её на сегодня через редактирование.

Незавершённое автоматически появляется на текущий день, в том числе после нескольких дней без запуска. Дубликаты за пропущенные дни не создаются. Выполненную задачу для переноса сначала нужно снова сделать открытой.

### Результат дня

Выберите прошлый день: на том же месте появится **только список выполненных в этот день задач**, без редактирования. Незавершённые уже перенесены на сегодня. Сохраняется день выполнения, а не первоначального планирования; смена часового пояса не переносит завершённые задачи между рекапами.

## Статистика и календарь

За день доступны работа, отдых, AFK, почасовой график, приложения и история интервалов. Доля работы равна `работа / (работа + отдых)`: AFK, паузы и пробелы в знаменатель не входят. Если активного времени нет, показывается отсутствие данных, а не ошибочный процент.

Переключайте месяцы, нажимайте на дни для просмотра статистики и задач. Рядом доступны месячные и недельные итоги.

Каждый квадрат разделён **вертикально**:

| Половина | Показатель | Фиксированная шкала |
| --- | --- | --- |
| Левая, зелёная | Время работы | 0; меньше 1 ч; от 1 до 4 ч; от 4 до 8 ч; 8 ч и больше |
| Правая, синяя | Сумма весов выполненных задач | 0; 1–4; 5–9; 10–14; 15 и больше |

Шкалы одинаковы между месяцами. Ноль работы, отсутствие активности и будущие даты различаются. Плановые задачи не окрашивают день как выполненный. Наведение или фокус показывает подробности; выбранный день имеет числовую статистику. На узком экране время сокращено до секунд, минут или целых часов.

## Исправление истории

1. Выберите день и найдите запись в истории.
2. Откройте изменение интервала и выберите работу, отдых или AFK.
3. Для исправления части записи задайте границы времени.
4. Примените изменение и проверьте обновлённые итоги.

Можно выделить несколько записей и изменить категорию всей группы. Например, отметить просмотр учебного видео как работу или исправить ошибочно определённый AFK.

Правки хранятся отдельно от наблюдений. У исправленной записи доступна отмена; графики пересчитываются. Разделение сохраняет общую длительность без двойного учёта.

## Экспорт и резервные копии

### Расположение данных

| Что | Путь по умолчанию |
| --- | --- |
| Установленное приложение | `%LOCALAPPDATA%\Programs\WorkLifeBalance` |
| История, задачи и настройки | `%LOCALAPPDATA%\WorkLifeBalance\activity.db` |
| Резервные копии | `%LOCALAPPDATA%\WorkLifeBalance\backups` |
| Журнал ошибок | `%LOCALAPPDATA%\WorkLifeBalance\errors.log` |

Каталог данных можно открыть через адресную строку Проводника. Не редактируйте работающую базу вручную.

### CSV и JSON

В **«Данные и запуск»** выберите даты и формат, затем нажмите «Экспорт». Один экспорт охватывает до 366 календарных дней включительно.

В него входят итоговые интервалы с правками, паузы и выполненные задачи. В JSON задачи находятся в `completedTodos`; в CSV это строки `Todo` с нулевой длительностью, названием, `task_weight` и `task_id`. CSV защищает значения от интерпретации как формул.

Экспорт нужен для анализа, **не для полного восстановления**. Открытые планы, исходные наблюдения и обратимые правки сохраняются в SQLite-копии.

### Создание и восстановление копии

Нажмите **«Создать копию»**: согласованный снимок SQLite появится в `backups`. Не копируйте открытый `activity.db` отдельно от файлов WAL: такая копия может оказаться неполной.

Для восстановления приостановите учёт, выберите копию и подтвердите замену словом `ВОССТАНОВИТЬ`. После проверки результата возобновите учёт.

Перед заменой автоматически создаётся страховочная копия. **Восстанавливается вся история**, не только открытый день. Текущие настройки сохраняются. Копия схемы v4 заменяет также все задачи; старая v3 восстанавливает историю времени, не меняя нынешние задачи. Повреждённые, несовместимые копии и копии с данными из будущего не принимаются.

Внешнюю копию можно вернуть в `backups` с исходным именем из 32 hex-символов и расширением `.db`, затем обновить страницу. Перед миграциями сохраняются файлы вида `activity.db.before-v4.bak`. Восстановление повреждённой основной базы описано в [руководстве](docs/user-guide.md).

### Очистка

Срок хранения `0` означает отсутствие ограничения. Положительное значение используется кнопкой **«Очистить по сроку»**. Фонового автоматического удаления нет.

Очистка выбранных дней, по сроку или всей истории требует паузы и подтверждения `УДАЛИТЬ`. Удаляются также выполненные задачи соответствующего временного диапазона, но открытые планы сохраняются. Перед удалением создаётся копия.

Копии и ранее скачанные экспорты не удаляются автоматически и могут содержать уже удалённую историю. Удаление записей не гарантирует физическое стирание с диска или из резервных копий Windows.

## Обновление и удаление

### Обновление из исходников

Создайте копию через интерфейс, полностью завершите трекер и Firefox. Из корня проекта:

```powershell
git pull --ff-only
./scripts/build.ps1
```

Для установленной копии повторите установку:

```powershell
./.artifacts/release/install.ps1 -Launch
```

При работе из папки сборки используйте `./scripts/start.ps1`. Проверьте настройки, историю и Firefox. Если путь помощника не изменился, повторная регистрация обычно не нужна. Автоматической загрузки обновлений нет.

Если `git pull --ff-only` отказался из-за расходящейся истории или локальных изменений, сначала сохраните и согласуйте свои правки. Не удаляйте их ради обновления.

### Удаление установленной копии

Завершите трекер и Firefox. В PowerShell:

```powershell
& "$env:LOCALAPPDATA\Programs\WorkLifeBalance\uninstall.ps1"
```

По умолчанию данные остаются. Чтобы удалить также стандартный каталог истории, задач, настроек и копий:

```powershell
& "$env:LOCALAPPDATA\Programs\WorkLifeBalance\uninstall.ps1" -DeleteData
```

Второй вариант дополнительно требует ввода `DELETE`. Экспорты в других папках и отдельные тестовые каталоги не затрагиваются. Расширение удаляется отдельно через `about:addons` в Firefox.

При работе только из папки сборки установщик удаления не применяется. Отключите автозапуск, завершите трекер и Firefox, снимите регистрацию через `./scripts/register-firefox.ps1 -Unregister`, затем уберите папку сборки. Стандартный каталог данных остаётся отдельно.

## Если что-то не работает

| Проблема | Что проверить |
| --- | --- |
| Страница не открывается | Запущен ли трекер и есть ли значок в трее. Нужны `127.0.0.1`, правильный порт и `http`, не `https` |
| Порт 47831 занят | Трей → «Порт веб-интерфейса…» → свободный порт → перезапуск. Чужие процессы завершать не нужно; другой порт не выбирается молча |
| Хоткей не работает | Запущен ли трекер. Проверьте ошибку регистрации и смените занятое сочетание. При паузе хоткей не возобновляет сбор |
| Нет уведомлений | Настройки Windows и «Не беспокоить». Состояние видно в трее и интерфейсе |
| Видео засчиталось как AFK | Воспроизведение не является вводом. Увеличьте порог или отключите авто-AFK; прошлое исправьте вручную |
| Рабочий сайт всё ещё отдых | Нужны расширение, соединение и активное окно Firefox. Правило влияет только на новые посещения; неизвестная вкладка остаётся отдыхом |
| Расширение не устанавливается | Для постоянной установки нужен подписанный XPI, не ZIP, и Firefox 142+ |
| Файлы сборки заняты | Завершите трекер, его тестовые экземпляры и Firefox, удерживающий NativeHost |
| PowerShell блокирует скрипт | Проверьте происхождение файлов и ограничения системы. Используйте разрешённый способ запуска, не отключайте корпоративные политики безопасности |
| База недоступна или повреждена | Не удаляйте её. Сохраните каталог данных и изучите `errors.log`; приложение не пересоздаёт базу молча |

### Firefox: `No such native application com.worklifebalance.tracker`

Firefox не смог обнаружить или принять регистрацию помощника. Откройте **обычную PowerShell из меню Windows** от того же пользователя, что запускает браузер:

```powershell
reg query "HKCU\Software\Mozilla\NativeMessagingHosts\com.worklifebalance.tracker" /ve
```

Значение должно указывать на существующий `firefox-native-host.json`, а его `path` на существующий `WorkLifeBalance.NativeHost.exe`. ID расширения: `work-life-balance@local.invalid`; внутренний UUID Firefox здесь не нужен.

Если ключа нет или путь устарел, завершите трекер и Firefox и повторите установку из готовой сборки. Для запуска из репозитория вместо установки выполните `./scripts/register-firefox.ps1`. Затем снова запустите трекер и Firefox.

Расширение использует **Native Messaging, не HTTP**: отсутствие запросов во вкладке «Сеть» не означает бездействие. Ошибки расширения смотрите через `about:debugging#/runtime/this-firefox` → Work Life Balance → «Исследовать». Успех регистрации или headless-теста в изолированной среде не доказывает доступность помощника в личном Firefox.

## Приватность и ограничения

- Данные локальные. Нет облачной синхронизации, телеметрии, CDN, внешних шрифтов и автоматических проверок обновлений.
- Сервер слушает только `127.0.0.1`, без доступа из LAN. Изменяющие запросы защищены токеном, проверками Host и Origin.
- Сохраняются интервалы приложений и активных вкладок, не все фоновые вкладки или полная история браузера.
- Из URL удаляются имя/пароль пользователя, query и fragment. Можно сохранять домен либо URL с путём. Заголовки тоже могут содержать личные сведения: берегите базу и копии.
- Содержимое страниц, скриншоты, текст ввода и нажатые клавиши не записываются. Для idle используется время последнего системного ввода.
- Приватные окна не раскрывают адреса и заголовки; при отсутствии сведений о вкладке учитывается только Firefox как приложение.
- Загрузка зависимостей и подпись расширения требуют внешнего доступа, но не являются частью фоновой работы установленного трекера.
- Поддерживаются Windows x64 и Firefox, один подключённый профиль с несколькими окнами. Часовой пояс отчётов системный.
- EXE и PowerShell-скрипты не имеют Authenticode-подписи издателя. Видимость уведомлений и доступность Win-сочетаний зависят от Windows.

## Разработка и проверки

Стек: C#/.NET 10, ASP.NET Core, SQLite, React, TypeScript, Vite, Recharts, Firefox WebExtension. Зависимости зафиксированы lock-файлами. Domain не зависит от Windows или БД; изменения учёта и задач проходят через общий координатор.

### Frontend с горячим обновлением

Запустите backend, затем:

```powershell
cd src/web
npm ci
npm run dev
```

Vite доступен на `http://127.0.0.1:47832` и проксирует API на `47831`. Для тестового backend можно заранее задать `$env:WLB_DEV_API_PORT = '47833'`. Для обычной работы dev-сервер не нужен.

### Логика, линтер и сборка

Из корня, после установки frontend-зависимостей:

```powershell
./scripts/test.ps1
```

Скрипт запускает .NET-тесты, проверки сборщика Firefox, ESLint, проверку форматирования и сборку frontend. Нативные Windows-тесты требуют интерактивной сессии. Playwright запускается отдельно.

### Браузерные тесты на отдельной базе

**Не запускайте их на личной истории:** тесты меняют настройки, задачи и интервалы, проверяют удаление и восстановление. Нужны новый тестовый каталог и свободный порт. После сборки из корня:

```powershell
. ./scripts/dotnet.ps1
& $Dotnet run --project tools/WorkLifeBalance.Smoke -- --seed .local/readme-ui-check 47833
$testData = (Resolve-Path .local/readme-ui-check).Path
Start-Process -FilePath '.artifacts/release/WorkLifeBalance.Host.exe' -ArgumentList '--data-dir', ('"' + $testData + '"') -WindowStyle Hidden
```

Дождитесь, когда откроется `http://127.0.0.1:47833`, затем в той же PowerShell:

```powershell
Push-Location src/web
try {
    $env:WLB_TEST_URL = 'http://127.0.0.1:47833'
    npm run test:e2e
} finally {
    Remove-Item Env:WLB_TEST_URL -ErrorAction SilentlyContinue
    Pop-Location
    Start-Process -FilePath '.artifacts/release/WorkLifeBalance.Host.exe' -ArgumentList '--data-dir', ('"' + $testData + '"'), '--shutdown' -WindowStyle Hidden -Wait
}
```

Тесты используют установленный Microsoft Edge в headless-режиме; снимки сохраняются в `src/web/test-results`. Для нового seed выберите новое имя каталога: существующая база не перезаписывается. Обычный Firefox не переключается на тестовую базу автоматически.

Проверка задач от 25.09.2026: **108 .NET-тестов и 14 Playwright-проверок**, включая экран 320 px. Это результат конкретного прогона, не гарантия проверки всех конфигураций Windows. Подробности: [задачи](docs/todos.md), [итерация 4](docs/iteration-4.md).
