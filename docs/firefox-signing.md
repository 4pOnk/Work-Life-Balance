# Отправка Firefox на подпись

По явному разрешению пользователя расширение Work Life Balance 0.2.0 отправлено в Mozilla Add-ons для самостоятельного распространения (unlisted, не публичный каталог).

- Архив: `.artifacts/work-life-balance-firefox-0.2.0.zip`.
- Внутри только шесть файлов расширения: manifest.json, background.js, collector.js, popup.html, popup.css, popup.js. База и история не отправлялись.
- Проверка Mozilla: без ошибок и предупреждений.
- 20 сентября 2026: подтверждён статус **Approved**, версия 0.2.0. Подписанный XPI скачан в `.artifacts/work-life-balance-firefox-0.2.0-signed.xpi`; установка в личный Firefox ещё не подтверждена.
- Подписанный файл Mozilla: https://addons.mozilla.org/firefox/downloads/file/5042655/09852b1be9e04c149eab-0.2.0.xpi
- Страница завершённой отправки: https://addons.mozilla.org/en-GB/developers/addon/09852b1be9e04c149eab/submit/finish
- Кабинет: https://addons.mozilla.org/en-GB/developers/addons

Mozilla сообщит о готовности по электронной почте. После получения подписи скачать XPI из кабинета и установить через Firefox `about:addons` → «Установить дополнение из файла». Не заменять подписанный XPI самостоятельно пересобранным ZIP. Последующие версии отправлять как обновления существующего дополнения.

Этот документ обновляет прежние замечания об отсутствии отправки и подписи. Подпись получена; постоянная установка остаётся незавершённой до установки подписанного файла. Автоматическое одобрение не исключает последующую ручную проверку Mozilla.

## Проверка подписанного XPI

20 сентября 2026 выполнен `node tests/signed-smoke.mjs` из `extensions`. Неизменённый XPI скопирован в новый изолированный профиль Firefox и загружен обычным механизмом установки, без temporary-add-on API и отключения проверки подписей. Firefox подтвердил `active=true`, `signedState=2`, `appDisabled=false`, `userDisabled=false`. SHA-256 исходного и установленного файлов совпал: `374A3BA2BF054DCA5008B3BF3946C70ED53D84E5126760045A6308A42225474A`.

Проверка прошла: подписанное расширение → зарегистрированный NativeHost → изолированный тестовый named pipe; получено сообщение `version=1, sequence=1`. Основной трекер и личная база в тесте не участвовали. Тестовый Firefox завершён. Профиль теста сохраняется в `.local/signed-firefox-*` для диагностики.

В личном профиле также обнаружена активная подписанная версия 0.2.0 с правильным ID, но пользователь сообщает `No such native application`. Успех изолированного теста не означает устранение этой ошибки; причина различия пока не установлена.

Дополнительная диагностика: SHA-256 XPI в личном профиле также совпадает. Запрос `GetPackageFullName` показывает отсутствие package identity как у диагностической оболочки, так и у личного Firefox; `NtQueryKey` показывает обычный путь `\REGISTRY\USER\<SID>\Software\Mozilla\NativeMessagingHosts\com.worklifebalance.tracker`. Таким образом, предположение о MSIX-перенаправлении не подтверждено. Скрипт `scripts/diagnose-firefox.ps1` выполняет эти проверки только на чтение. Для независимого сравнения требуется прочитать значение регистрации из обычной пользовательской PowerShell, не порождённой средой агента.

Проверка пользователем из обычной PowerShell подтвердила: ключ отсутствует вне среды агента. Следовательно, прежние проверки регистрации и headless-тесты не подтверждали доступность ключа обычному Firefox. После регистрации помощника из обычной пользовательской PowerShell пользователь подтвердил успешное подключение личного Firefox. Постоянная установка подписанной версии 0.2.0 и доступность NativeHost подтверждены. Точный механизм изоляции не установлен; не утверждать, что это именно MSIX.
