# Итерация 4: поставка и управление данными

## Реализовано

- .NET SDK 10.0.401, runtime/Microsoft.Data.Sqlite 10.0.12; закреплённые зависимости и runtime assets. Self-contained win-x64 в `.artifacts/release`. Node.js и установленный .NET не требуются для запуска EXE.
- Пользовательские `install.ps1`/`uninstall.ps1`, ярлык меню «Пуск», Native Messaging HKCU, автозапуск через интерфейс (по умолчанию выключен). Без повышения до администратора. Подписанный Firefox 0.2.0 включён в текущую поставку; новых публикаций/подписаний не было.
- CSV/JSON-экспорт диапазона до 366 дней, UTC-границы и часовой пояс, фактическая классификация после поправок. CSV защищён от формульной инъекции.
- SQLite online backup, список копий, транзакционное восстановление истории, страховочная копия перед восстановлением/удалением. Настройки при восстановлении сохраняются. Восстановление принимает только идентификатор локальной копии, не произвольный путь.
- Подтверждаемое удаление диапазона/всей истории/по сроку хранения. Пауза обязательна. Границы интервалов разрезаются, сохраняются приоритет и обратимость правок за пределами удалённой области. Предпочтение срока сохраняется, но фонового удаления нет.
- Повреждённая/новая/недоступная база не пересоздаётся. При отказе конструктора закрывается соединение. Неверная копия не заменяет текущую историю.
- Руководство пользователя, правила установки/обновления/удаления, технические ограничения восстановления.

## Проверено 20 сентября 2026

- 74 .NET unit/integration/native-теста (67 + 7): AFK/пауза/DST, миграция v1 → v3 с копией, checkpoint, browser protocol, коррекции и календарь, удаление/восстановление, приоритет разделённых коррекций, повреждённая/недоступная/новая БД, секреты в логах, CSV.
- 6 тестов WebExtension-сборщика.
- 8 Playwright-проверок на реальном изолированном backend `47833`: настройки, процессы, AFK/пауза, CSRF/Origin, правки, календарь, desktop/mobile, экспорт, подтверждение удаления, восстановление. Плюс проверка форматирования и ESLint/TypeScript/Vite.
- Native stdio → CurrentUserOnly pipe → coordinator → SQLite: очищенный URL, повторное сообщение, потеря соединения; успешно с новым автономным мостом.
- Windows smoke на отдельной базе: глобальный Win+Shift+N при другом активном окне; настоящий idle с коротким порогом и ретроспективным AFK; возврат хоткеем; занятый порт без остановки учёта; аварийное завершение собственного тестового процесса и восстановление без начисления простоя; штатный IPC shutdown. Все шаги PASS, не SKIP. Первый запуск отказался из-за ещё занятого порта; после штатной остановки пользовательского экземпляра проверка повторена успешно.
- Новая версия запущена с прежней личной БД: порт 47831, `TrackerError=null`, `HotkeyError=null`, Firefox connected. Создана отдельная копия личной базы; удаление и восстановление проверялись только на синтетической истории.
- Текущий рабочий Firefox пока использует ранее зарегистрированный помощник из `.artifacts/app`; его регистрация не менялась. Старую папку не удалять до установки новой поставки из обычной PowerShell. Новый self-contained NativeHost проверен отдельно и включён в архив.
- У frontend нет внешних запросов (Playwright), зависимости поставляются локально. Логи не включают URL/заголовки/сообщения исключений (автотест); анализ исходников не выявил runtime HTTP-клиентов к внешним сервисам. Дополнительная 31-секундная выборка TCP-соединений тестового процесса вне sandbox с доступной диагностикой не обнаружила non-loopback peers. Это выборочная проверка TCP, не полный packet capture всех протоколов.

## Измерения

Тестовый процесс, обычный сбор без открытого web UI, 302,46 секунды: CPU 1,016 с, то есть 0,336% одного ядра; working set 72,68–85,17 МиБ. Сумма SQLite/SHM/WAL выросла с 131440 до 2619920 байт, после штатного закрытия остался `activity.db` 40960 байт. Это преимущественно журнал WAL, не рост истории на 2,5 МБ каждые пять минут. Запись транзакции остаётся примерно раз в секунду; одинаковые наблюдения объединяются в интервалы.

Сетевая часть первого замера была недоступна из sandbox, поэтому пустой результат не принят за доказательство; проведён отдельный замер с доступом к сетевым счётчикам. Скрипт теперь явно сообщает доступность проверки. Пять минут не заменяют длительную приёмку 8–24 часа. CPU/память при большой многолетней базе или массовом экспорте не измерялись.

## Воспроизводимость

```powershell
./scripts/build.ps1
./scripts/package-release.ps1
./scripts/test.ps1
# Отдельная НОВАЯ база, не личная история:
. ./scripts/dotnet.ps1
& $Dotnet run --project tools/WorkLifeBalance.Smoke -- --seed .local/acceptance 47833
Start-Process .artifacts/release/WorkLifeBalance.Host.exe -ArgumentList '--data-dir','"C:\path\to\.local\acceptance"' -WindowStyle Hidden
$env:WLB_TEST_URL='http://127.0.0.1:47833'
Push-Location src/web
npm run test:e2e
Pop-Location
./scripts/measure.ps1 -ProcessId <test-host-pid> -DataDirectory .local/acceptance -Seconds 300
```

Для native smoke освободить 47831 и Win+Shift+N, затем `& $Dotnet run --project tools/WorkLifeBalance.Smoke -- .artifacts/release/WorkLifeBalance.Host.exe .local/native-acceptance`. Само приложение и его данные в ходе теста отдельные; после теста снова запустить основной экземпляр.

## Ручная приёмка и ограничения

- Код четвёртой итерации реализован, но полная эксплуатационная приёмка ещё не закрыта: перезагрузка/вход Windows с автозапуском, сон/блокировка и видимость уведомлений в обычной сессии, установка/удаление из обычной PowerShell, длительный прогон 8–24 часа. Эти действия в текущем прогоне не выполнялись, чтобы не прерывать пользовательскую сессию и не менять рабочую регистрацию Firefox.
- Проверена автономная сборка и запуск, но отдельной чистой Windows VM без системного .NET в этом прогоне не было.
- Автозапуск показывает точную запись HKCU Run, но Windows может отдельно выключить её через диспетчер задач. Реестр среды агента не считается доказательством регистрации в пользовательском Firefox.
- Authenticode-подписи EXE/установщика нет. Signed XPI уже предоставлен и проверен пользователем ранее. Неподписанный ZIP не выдаётся за готовое дополнение.
- Копии и экспорты содержат чувствительную историю; удаление записей не удаляет их копии и не гарантирует физического стирания SSD. Фоновая очистка отсутствует, полный каталог удаляется только явным `uninstall.ps1 -DeleteData` с подтверждением.
- Backup API SQLite синхронный; во время копии/восстановления координатор занят. На больших базах операция может быть заметной, её длительность ещё не профилировалась. Сбор после долгой задержки оставляет неизвестный пробел, а не начисляет разрыв последнему приложению.
- Vite сообщает предупреждение о bundle около 606 КБ (181 КБ gzip); это не ошибка сборки, код графиков пока не разбит на ленивые chunks.

Официальные основания: [.NET 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0), [SQLite online backup](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup), [HKCU Run](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).
