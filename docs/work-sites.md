# Рабочие сайты (24.09.2026)

В разделе «Рабочие сайты» добавлять домен или HTTP/HTTPS-ссылку. Сохраняется только домен: без пути, query, fragment и регистра, IDN приводится к ASCII. Дубликаты объединяются. URL с логином/паролем, некорректные имена и wildcard-правила не принимаются. Поддерживаются полные DNS-имена и IPv4; IPv4 сопоставляется только точно.

Правило `example.com` включает `example.com` и `docs.example.com`, но не `notexample.com` и не `example.com.evil.net`. Правило `docs.example.com` не включает родительский `example.com`. Условие определяется по очищенному домену активной вкладки Firefox, независимо от настройки хранения пути. Фоновая вкладка не приносит работу. Приватные, неизвестные и устаревшие вкладки не дают совпадения.

Список действует с момента сохранения, в том числе для текущей активной вкладки. Старая история автоматически не пересчитывается; изменение/удаление правила не отменяет уже записанную работу. AFK и ручные правки приоритетнее. После отмены ручной правки восстанавливается исходная категория, а не категория по сегодняшнему списку. Пересчёт правил executable не меняет историю сайтов.

`workSites: string[]` хранится внутри существующего JSON настроек. Старые настройки без поля получают пустой список; миграции SQLite и обновление Firefox-расширения не нужны. Изменения используют существующий `PUT /api/v1/settings`, валидацию и CSRF-защиту. Источник категории в деталях — «Правило рабочего сайта». При переключении вкладки координатор одновременно обновляет наблюдение и категорию, без задержки до следующего тика.

## Проверки без release

- 90 .NET-тестов: домены/поддомены, ложные совпадения, IDN, нормализация ссылок, приватность, старые настройки, сохранение категории после удаления правила/перезапуска, AFK и ручные правки, смена вкладки и отключение браузерного канала.
- Playwright: добавление/дубликаты/удаление, перезагрузка страницы, сохранение остальных настроек без потери сайтов, ошибки валидации, desktop/mobile со снимками.
- TypeScript `--noEmit` и ESLint. Backend собирается только в Debug; `publish`, release/package и production frontend build не выполняются.

```powershell
. ./scripts/dotnet.ps1
& $Dotnet test WorkLifeBalance.sln --no-restore
& $Dotnet build src/WorkLifeBalance.Host -c Debug --no-restore
# Подготовить НОВЫЙ отдельный тестовый каталог:
& $Dotnet run --project tools/WorkLifeBalance.Smoke --no-restore -- --seed .local/sites-test 47835
# Запустить Debug host с --data-dir, указывающим на этот каталог.
# При локальном SDK для запуска apphost задать DOTNET_ROOT=.artifacts/dotnet10 (абсолютный путь).
cd src/web
$env:WLB_DEV_API_PORT='47835'
npm run dev -- --port 47836
```

В другой консоли из `src/web`: `$env:WLB_TEST_URL='http://127.0.0.1:47836'; npx playwright test tests/sites.spec.ts`. Vite proxy предназначен для разработки: он переписывает Origin к выбранному loopback backend. Тесты защитного HTTP middleware следует направлять на backend напрямую, а не через этот proxy.

Первоначальные проверки выполнялись отдельно: dev-предпросмотр на 47836 использует только тестовую историю и отдельные настройки. После уточнения пользователя 24.09.2026 изменения применены к личному экземпляру на 47831: создана SQLite-копия, выполнен штатный перезапуск с новой Debug-сборкой, проверены сохранение прежних настроек, наличие раздела «Рабочие сайты», отсутствие ошибок учёта/хоткея и подключение Firefox. Отдельная релизная оптимизация, упаковка и публикация не выполнялись.
