# Итерация 1: результат

Дата проверки: 19 сентября 2026. Среда: Windows 11 (build 26200), .NET SDK 9.0.317, Node.js 22.18.0.

## Реализовано

- Разделённые проекты Domain, Application, Infrastructure, Windows и Host, React/TypeScript frontend.
- Реальный foreground-коллектор, локальная SQLite-база с миграцией, объединение соседних интервалов и checkpoint раз в секунду.
- Редактируемый список рабочих executable, список реальных запущенных приложений, поиск и группировка экземпляров.
- Авто-AFK с настраиваемым порогом, ретроспективным диапазоном, ручной AFK, пауза, Win32-события блокировки/сна.
- Глобальный `Win + Shift + N`, смена хоткея и диагностика коллизии, tray-команды и нативные уведомления о переходах.
- Единственный экземпляр для одного каталога данных, IPC открытия интерфейса/завершения, работа трекера при недоступном HTTP-порту.
- Реальные дневные счётчики, последние интервалы и настройки на `127.0.0.1:47831`.
- Защита HTTP от cross-origin/CSRF, CSP, локальные assets, отсутствие исходящих запросов frontend.
- Воспроизводимые scripts/build.ps1, scripts/test.ps1, scripts/start.ps1 и scripts/stop.ps1; готовая Release-сборка в `.artifacts/app`.

Domain-тесты проверяют точный короткий AFK-порог, перенос времени до его начала через полночь, единственность уведомлений о переходе, ручной AFK при вводе, паузу, lock/suspend/resume, необъяснимые разрывы и монотонность. SQLite-тесты проверяют транзакционность, отсутствие двойного счёта, объединение записей и DST-дни длиной 23/25 часов.

Playwright проверяет добавление/удаление рабочего процесса, сохранение настроек после перезагрузки страницы, ручной AFK, паузу и её приоритет над хоткеем/API. Также проверены запросы без токена, чужие Origin/Host, отрицательный порог AFK и отсутствие внешних запросов страницы.

## Что нельзя считать проверенным автоматически

- Live-проверка авто-AFK с порогом 3 секунды была пропущена из-за продолжающегося системного ввода: максимальный наблюдаемый idle в последнем прогоне — 3687 мс, без гарантированного окна для следующего опроса коллектора. Алгоритм короткого порога и ретроспективный пересчёт проверены детерминированными тестами. Smoke-tool помечает этот случай `SKIP`, а при достаточном idle и отсутствии перехода завершится ошибкой.
- Физический сон/блокировка компьютера не инициировались во время работы пользователя. Системная подписка реализована; переходы проверены тестами, но реальный цикл sleep/resume остаётся ручной проверкой.
- API отправки нативных уведомлений подключён. Видимость уведомления на экране и влияние режима «Не беспокоить» требуют проверки пользователем; успешный API/хоткей-тест не доказывает видимость toast.
