# Архитектура

## Компоненты

- `Domain`: чистая функция перехода состояния, классификация, интервалы `[start,end)`, отчёт дня и DST-границы. Зависимостей от ОС/БД нет.
- `Application`: координатор с одним `SemaphoreSlim`, интерфейсы источников и хранилища. Таймер, API, хоткей и session-события проходят через один порядок записи. Новое состояние публикуется только после успешной транзакции.
- `Infrastructure`: SQLite/WAL, миграции до `user_version=4`, UTC-якорь с `Stopwatch`, ограниченный локальный журнал без заголовков/URL/текстов исключений, пользовательский канал Native Messaging. Таблицы `pauses` и `todos` хранят паузы и задачи отдельно от активности.
- `Windows`: Win32 foreground/PID, `GetLastInputInfo`, список процессов, `RegisterHotKey` с `MOD_NOREPEAT`, WTS/power-события, WinForms tray/dispatcher и системные уведомления.
- `Host`: композиция, пользовательский named pipe и mutex, loopback HTTP, CSRF/Host/Origin, static frontend.
- `web`: React/TypeScript. Получает готовые итоги от backend; повторного алгоритма учёта в браузере нет.

## Переходы

| Исходное состояние / событие | Результат |
|---|---|
| Активен, достигнут порог idle | Авто-AFK с последнего ввода или начала текущего периода сбора |
| Авто-AFK, появился ввод | Активен с момента наблюдения возврата |
| Активен, хоткей | Ручной AFK с текущего момента |
| Любой AFK, хоткей в разблокированной сессии | Активен, новый baseline idle |
| Ручной AFK, мышь/клавиатура | Ручной AFK сохраняется |
| Пауза, хоткей | Пауза сохраняется, уведомление о паузе |
| Пауза, возобновление | Активен, новый baseline, без начисления паузы |
| Lock/suspend | Системный AFK; ручной режим, если был, сохраняется |
| Resume при всё ещё заблокированной сессии | AFK продолжается |
| Unlock после системного AFK | Активен; ручной AFK сохраняется, если был |

`Paused`, ручное отсутствие и признаки `Locked`/`Suspended` разделены. При паузе интервалы не начисляются. Авто-AFK не отменяется простым увеличением порога после его подтверждения.

## Данные и восстановление

`activity` содержит исходные интервалы и категорию по правилу на момент записи. Соседние одинаковые записи объединяются. `away` содержит отдельные AFK-диапазоны с причиной; отчёт накладывает их на исходную активность и не считает перекрытия дважды. `settings` хранит валидированный JSON.

Microsoft.Data.Sqlite зафиксирован на 10.0.12, SQLitePCLRaw.bundle_e_sqlite3 на 3.0.5. Полный граф зависимостей зафиксирован в lock-файлах, включая win-x64 runtime.

Каждый замер сохраняется транзакционно (обычно раз в секунду). Это осознанный выбор первой итерации: потеря при аварии ограничена несохранённым хвостом, без журнала из одной строки на секунду. Оптимизация частоты fsync должна сохранять ясную семантику checkpoint.

Трекер не продлевает последний интервал до текущего времени при запуске. Разрыв коллектора больше пяти секунд без известного AFK считается неизвестным. Известный сон/отсутствие сохраняется как AFK. В первой итерации паузы и отсутствие запущенного трекера оба видны как пробелы в интервалах; отдельная визуальная детализация причин пробелов относится к будущему dashboard.

Время привязано к UTC в начале процесса, далее идёт по монотонным часам; изменение системных часов в текущем запуске не меняет длительности. Системный часовой пояс используется при запросе отчёта. Его смена пересчитывает представление истории.

`corrections` хранит диапазоны пользовательских правок и идентификатор группового действия. Отмена помечает действие отменённым, не меняя исходные наблюдения. Последняя неотменённая правка имеет приоритет над AFK и правилами. `rule_revisions` сохраняет снимок правил executable и верхнюю границу исторического пересчёта. Firefox не классифицируется по executable: известный неприватный домен сопоставляется с `TrackerSettings.WorkSites`, иначе отдых. Категория сайта сохраняется в исходном интервале и не меняется при последующем редактировании списка сайтов или пересчёте правил процессов. Источник рабочей браузерной категории в отчёте — `siteRule`. Отчёт делит интервалы на границах правок, AFK и пересчётов, не заполняя пробелы. Миграция v1 → v2 сохраняет резервную копию `activity.db.before-v2.bak` через SQLite backup API.

`NativeHost` — отдельный короткоживущий stdio-мост Firefox, без логики учёта. Бинарные сообщения ограничены 32 КБ; named pipe доступен текущему Windows-пользователю. `Application/BrowserFeed` проверяет версию, последовательность и свежесть сообщения, сопоставляет его с foreground HWND. Метаданные действуют не более 2,5 секунд без нового наблюдения; соединение считается потерянным через 5 секунд без heartbeat. При разрыве метаданные сбрасываются. Время начисляет только основной координатор, не расширение. Формат и ограничения описаны в [firefox.md](firefox.md).

## Локальный HTTP

### Задачи

`ITodoStore` — отдельный контракт хранилища; операции проходят через gate координатора, включая API-запросы и чтение отчётов. `TodoDraft` валидирует название, вес и плановую дату. Локальный текущий день вычисляется из серверного `IClock`, не из даты браузера. Пауза/AFK не блокируют планирование. Каждое изменение задачи — одна атомарная SQLite-команда под общим gate.

В `todos` хранятся GUID, название, вес, плановый `DateOnly.DayNumber`, nullable UTC-миллисекунды и локальный день выполнения. Для открытых задач эффективная дата — `max(planned_day, today)`. Перенос не требует записей в полночь и не создаёт копий; после простоя просроченные задачи сразу попадают на сегодня. Выполнение фиксирует текущий день, повторное `completed=true` не меняет момент. Снятие отметки возвращает задачу на сегодня. Прошлые выполненные задачи защищены от редактирования на сервере; смена часового пояса не меняет сохранённую дату рекапа.

Миграция v4 добавляет таблицу и индексы транзакционно, предварительно создавая `activity.db.before-v4.bak`. SQLite backup включает все задачи. Restore v4 заменяет их вместе с историей, restore v3 сохраняет существующие задачи. Удаление истории удаляет только завершённые задачи по UTC-моменту выполнения. JSON-экспорт включает `completedTodos`; CSV добавляет строки `Todo` с нулевой длительностью и столбцы `task_weight,task_id`.

- `GET /api/v1/todos?date=yyyy-MM-dd`: выбранный день, серверный сегодня и список.
- `POST /api/v1/todos`: `{title,weight,date}`; `PUT /api/v1/todos/{id}` — редактирование.
- `POST /api/v1/todos/{id}/completion`: `{completed: bool}`; `DELETE /api/v1/todos/{id}` — удаление.
- Dashboard дополнительно возвращает `todos`, а календарные дни — `taskCount`, `taskWeight`, `taskLevel`, `hasActivity`. Шкала веса независима от часов. Новые поля не меняют существующие категории или длительности.

### Остальные маршруты

- Только IPv4 loopback `127.0.0.1`, порт по настройке, по умолчанию `47831`.
- `/api/v1/session`: токен процесса для изменяющих запросов.
- `/api/v1/status`: состояние, текущие настройки, дневной отчёт, ошибка хоткея и активный порт.
- `/api/v1/processes`: сгруппированные запущенные процессы.
- `PUT /api/v1/settings?scope=future|history`: правила и параметры; порт применяется после перезапуска.
- `GET /api/v1/history?date=yyyy-MM-dd`: дневные интервалы и источник категории.
- `GET /api/v1/dashboard?date=yyyy-MM-dd&month=yyyy-MM`: дневной график и приложения, паузы/пробелы, календарь и недельные суммы; подробности в `iteration-3.md`.
- `POST /api/v1/corrections`: пакет диапазонов UTC `[start,end)` в миллисекундах и категория; возвращает `actionId`.
- `DELETE /api/v1/corrections/{actionId}`: отмена всего действия.
- `GET /api/v1/firefox/package`: локальный неподписанный архив расширения.
- `POST /api/v1/afk`, `POST /api/v1/pause`: последовательные команды координатору.

Изменяющие запросы требуют `X-WLB-Token`. Проверяются Host, Origin и cross-site Fetch Metadata. CORS не включён. Ответы не кешируются, действует CSP; строки из процессов выводятся React как текст.

Токен защищает от веб-страниц; это не защита от другого доверенного локального процесса в той же пользовательской сессии. IPC использует `CurrentUserOnly`, идентичность экземпляра привязана к пользователю и каталогу данных.

## Известные технические границы

### Архив и поставка (0.4)

`IHistoryArchive` отделяет обслуживание истории от обязательного контракта сборщика. Координатор сериализует архивные операции тем же gate. Удаление и восстановление допустимы только при паузе; перед изменениями создаётся SQLite online backup. При отказе копии изменение не начинается. Восстановление выполняется через ATTACH и транзакционную замену таблиц истории, не подменяет файл живой SQLite-сессии и сохраняет текущие настройки. Копия проверяется на целостность, версию, границы/перекрытия исходных интервалов. Источник `activity` после разрезания упорядочивается по времени, не по ID; поправки переупорядочиваются по исходному приоритету.

`GET /api/v1/storage`, `POST /api/v1/storage/backup`, `POST /api/v1/storage/restore` (`id`, `confirmation=ВОССТАНОВИТЬ`), `POST /api/v1/storage/delete` (`from`,`to` включительно либо `all`, `confirmation=УДАЛИТЬ`). Все изменяющие операции защищены штатным CSRF-токеном. `GET /api/v1/export?from=...&to=...&format=csv|json` отдаёт attachment с итоговой историей, а не сырой резервной копией. `GET/PUT /api/v1/startup` читает/пишет точную HKCU Run-команду текущей установки.

`RetentionDays` — сохранённое предпочтение подтверждаемой очистки, не скрытый фоновый таймер. Копии автоматически не удаляются. Поставляется self-contained win-x64; WinForms/ASP.NET runtime включены, расширение и native bridge используют прежний протокол v1. Подробности и ограничения: `user-guide.md`, `iteration-4.md`.

- SDK 10.0.401, .NET 10.0.12 LTS, self-contained win-x64. Системный .NET для поставки не нужен.
- В первой итерации записывается executable, без заголовков окон. Это достаточно для текущих правил и снижает сбор чувствительных данных.
- Firefox: поддерживается один подключённый профиль, несколько окон в нём. Постоянная установка требует подписи Mozilla; личный профиль не модифицируется автоматически.
- Нативные уведомления передаются Windows, но их видимость контролирует ОС. Собственная регистрация branded toast и упаковка возможны на этапе поставки.
- Перевод часов назад между разными запусками требует отдельной политики конфликтующих UTC-интервалов; текущая БД запрещает перекрывающуюся запись и показывает ошибку вместо порчи истории. Внутри одного запуска часы монотонны.

Официальные API: [GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow), [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey), [NotifyIcon.ShowBalloonTip](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon.showballoontip), [.NET support](https://dotnet.microsoft.com/en-us/platform/support/policy).
