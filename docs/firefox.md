# Firefox: установка и локальный протокол

## Установка

Требуется Firefox 142 или новее. Расширение не устанавливается в личный профиль автоматически. Сначала собрать приложение и зарегистрировать помощник для текущего пользователя:

```powershell
./scripts/build.ps1
./scripts/register-firefox.ps1
./scripts/start.ps1
```

Регистрация создаёт manifest в `.artifacts/app/firefox-native-host.json` и ссылку на него в `HKCU\Software\Mozilla\NativeMessagingHosts\com.worklifebalance.tracker`. Администратор не требуется. После переноса папки повторить регистрацию. Удаление регистрации: `./scripts/register-firefox.ps1 -Unregister`.

Важно: регистрацию выполнять из обычной PowerShell, открытой через меню Windows, а не только из среды агента. В обнаруженном случае ключ был виден агенту и его тестовому Firefox, но отсутствовал в обычной пользовательской сессии. Проверка из обычной PowerShell: `reg query "HKCU\Software\Mozilla\NativeMessagingHosts\com.worklifebalance.tracker" /ve`. После регистрации в обычной сессии пользователь подтвердил подключение. Подписанная версия 0.2.0 уже получена и установлена; актуальный результат и путь XPI: [firefox-signing.md](firefox-signing.md).

### Проверка сейчас

В Firefox открыть `about:debugging#/runtime/this-firefox`, выбрать «Загрузить временное дополнение» и файл `extensions/firefox/manifest.json`. Открыть обычную вкладку и проверить статус в панели расширения и локальном интерфейсе. Такая установка действует только до перезапуска Firefox.

### Постоянная установка

Сборка создаёт **неподписанный** `.artifacts/work-life-balance-firefox-0.2.0.zip`; этот же архив доступен из веб-интерфейса. Обычный Firefox не принимает его как постоянное дополнение.

Поддерживаемый путь: владелец расширения отправляет код на Mozilla Add-ons для подписи с самостоятельным распространением (unlisted), получает подписанный XPI, затем в `about:addons` выбирает меню шестерёнки → установку дополнения из файла. Для этого нужен аккаунт Mozilla. Отправляется код расширения, не база, логи или история пользователя. В рамках итерации внешняя отправка не выполнялась и требует отдельного разрешения. Отключение проверки подписей не предлагается.

Официальные требования: [подпись и распространение](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/), [самостоятельное распространение](https://extensionworkshop.com/documentation/publish/self-distribution/), [установка подписанного файла](https://extensionworkshop.com/documentation/publish/install-self-distributed/).

## Поведение и приватность

- Только активная вкладка сфокусированного окна Firefox; сервер дополнительно проверяет foreground-процесс и HWND. Поддерживается один подключённый профиль с несколькими окнами.
- Любая вкладка по умолчанию считается отдыхом. Категория меняется вручную в истории, целиком или частично. Видео не отменяет AFK.
- Закрытый интерфейс не мешает сбору. Закрытый трекер не запускается расширением: отображается отсутствие соединения.
- При потере связи продолжается учёт Firefox без известного адреса. Старый URL не продлевается бессрочно.
- Приватный доступ запрещён manifest; адреса приватных окон не собираются. Без сведений от расширения остаётся только процесс Firefox.
- До передачи удаляются userinfo, query и fragment. Backend повторяет очистку. В настройках можно оставить только домен либо домен и путь; изменение относится к новым наблюдениям, не удаляет старые адреса.
- Название страницы остаётся потенциально чувствительным: оно хранится локально, но не попадает в диагностический журнал. Содержимое страниц не читается, сохранённые URL и favicon не загружаются.
- Нет HTTP-запросов из сборщика. Разрешения расширения: `tabs`, `nativeMessaging`. Открытие статистики по кнопке ведёт только на `127.0.0.1`.

## Протокол v1

Firefox запускает `WorkLifeBalance.NativeHost.exe` через [Native Messaging](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_messaging). JSON UTF-8 обрамляется четырьмя байтами длины little-endian; предел сообщения 32 КБ. Помощник передаёт пакеты основному процессу через named pipe с `CurrentUserOnly`; разрешён единственный ID расширения `work-life-balance@local.invalid`. Это изоляция от веб-сайтов и других Windows-пользователей, не защита от вредоносного процесса того же пользователя.

Поля: `version`, возрастающий `sequence`, `observedAt` (Unix UTC ms), `focused`, `private`, `windowId`, `tabId`, `url`, `title`. Heartbeat примерно раз в секунду и события переключения. Допустимый возраст: не старше 5 секунд и не более 2 секунд в будущем. Повторная последовательность отклоняется; после нового соединения начинается новая последовательность. Длительность по этим timestamp не начисляется: её определяет координатор трекера.

Ответ: `version`, `ok`, `status`, `port`, `browserPath`. Адрес вкладки действителен до 2,5 секунд без обновления; статус связи устаревает через 5 секунд. Таймаут ответа расширения — 6 секунд, ожидания pipe — 10 секунд. URL ограничен 8192 символами, входной заголовок — 1024, сохраняемый — 512.

## Проверки разработки

Для проверки поиска и запуска помощника без личной истории:

```powershell
cd extensions
node tests/native-probe.mjs
```

Тест ставит диагностическое дополнение с тем же ID только во временный headless-профиль. Он отправляет техническое сообщение без URL и направляет помощник на неиспользуемый каталог данных. Ответ `WLB_PROBE_OK` с `tracker-offline` означает успешное обнаружение и запуск помощника, а не подключение основного трекера. Обычный профиль и подписанный XPI не изменяются. 20 сентября 2026 этот тест прошёл, но ошибка `No such native application` в личном профиле пользователя пока не устранена; успех временного профиля не считать доказательством исправления личного.

```powershell
cd extensions
npm ci
npm test
npm run lint
```

Для сквозной проверки нужен запущенный трекер с отдельным `--data-dir` на порту 47831 и зарегистрированный помощник:

```powershell
# Из extensions; обычный экземпляр сначала остановить.
node tests/firefox-smoke.mjs ../.local/iteration2-ui
```

Сценарий создаёт временный headless-профиль Firefox и устанавливает дополнение только в него. Переменная `WLB_NATIVE_DATA_DIR` задаётся внутри тестового процесса, не глобально. Проверяет соединение настоящего Firefox с помощником и трекером; корректность привязки URL к foreground отдельно покрывается детерминированными тестами. Это не полноценная ручная проверка переключения видимых окон и приватного режима.
